# 用 FFmpeg 把整张专辑的 MP4 切成带标签的 M4A

你是负责处理专辑音频的 CLI agent。给定一个专辑工作目录，读取曲目时间戳与专辑资料，调用 `ffmpeg` 实际切分音频，并用 `ffprobe` 验证结果。交付的是一首歌一个 `.m4a` 文件，可直接导入 Jellyfin 的 Music 库。

## 输入

- **原始 MP4**：一段包含整张专辑的音乐视频。使用用户指定的路径；如果目录里只有一个 MP4，可以直接使用。若有多个且无法确定来源，先问用户。
- **`timestamps.md` 或 `timestamps.png`**：每首歌的名称与开始时间。如果同时提供 Markdown 和图片，以 Markdown 为准；若发现两者冲突，指出差异，请用户确认。
- **`metadata.md`**：专辑名、专辑艺术家、演唱者以及已知的其他资料。它可能是普通 Markdown，不要求固定格式。以用户提供的信息为准；不要从目录名推断不确定的资料，也不要联网补全。

## 缺失信息时先报错

开始导出之前检查全部输入。发现必需文件、时间戳、歌名、专辑名、专辑艺术家或曲目演唱者缺失、读不清或相互冲突时，输出「输入错误」，一次列出问题、所在文件和受影响的曲目，并明确请用户提供什么。等用户补齐或确认后再切分、写标签和打包。不要跳过曲目、静默留空，也不要把专辑艺术家自动填成演唱者。

例如：`输入错误：metadata.md 未提供第 2 首「海岸线」的演唱者。请提供该曲演唱者，或明确确认哪些曲目共用同一位演唱者。` 对于明确标为可选的资料，若未提供，在交付说明中列出未填写的字段；若用户要求填写该字段，则先请用户补充。

## 读取并核对曲目表

1. 按时间戳文件列出的顺序提取曲目。支持 `M:SS`、`HH:MM:SS`、带小数的秒数、全角冒号，以及 `3：51韵河` 这种时间与歌名直接相连的写法。图片用可用的图像读取或 OCR 能力识别；看不清的数字或歌名不要猜。
2. 第 N 首的结束时间默认为第 N+1 首的开始时间，最后一首默认为源音频结束。若输入明确给了某首的结束时间或最后一首的结束时间，按提供值处理；源视频开头在第一首开始之前的内容不导出。
3. 用 `ffprobe` 检查源文件的音轨、编码和时长。确认开始时间严格递增，每首的时长为正，所有边界都在素材范围内且没有重叠。若有多个音轨，优先用明确标记的默认音轨；选择不明确时请用户确认。
4. 先列出「序号、歌名、开始、结束、输出文件名」。所有必需信息齐全且有效时继续；否则按上面的规则汇总报错，请用户补齐或确认。

## 切分和命名

- 在工作目录里创建一个与专辑同名的成品子目录，以 `metadata.md` 中的专辑名为准。例如工作目录为 `运河/`，专辑名为「运河」，成品就放到 `运河/运河/`。不额外创建 `output/` 层。若子目录已存在，可以保留其中的 `cover.jpg` 或 `cover.png`；若已有同名歌曲或其他来源不明的文件，先报告冲突，不覆盖或误打包。
- 文件名格式是 `01-第一首歌名.m4a`、`02-第二首歌名.m4a`，以此类推。序号按曲目表顺序生成，至少两位；替换文件名里的非法字符，但保留标签里的原始歌名。
- 只输出选定的音轨，不带源视频、字幕或章节。源音轨是 AAC 或 ALAC 时，优先用 `-c:a copy`，避免重新编码。可先提取一份临时的纯音频，再在这份文件上切分，避免使用视频关键帧作为定位依据。
- 如果源音轨无法直接封装为 M4A，说明需要转换；默认可编码为 ALAC，以免在解码后的音频上增加有损压缩。如果用户指定了其他编码，按用户要求处理。检查实际切口；压缩音频直接复制可能有少量帧级偏差。
- 每首歌的 `-t` 使用「结束时间减开始时间」，不要把下一首的绝对开始时间直接当作时长。用 `-n` 防止覆盖；保留原 MP4、时间戳文件和 `metadata.md`。

## 写入 M4A 标签

标签要写在每个音频文件里，不用给专辑目录本身写标签。可以在切分时通过 FFmpeg 的 `-metadata` 一次写入：

| FFmpeg 字段 | 取值规则 |
|---|---|
| `title` | 时间戳中的完整歌名，不加文件名前缀 |
| `track` | 曲目编号；已知总数时写 `2/12`，否则写 `2`。多碟时按提供的碟内编号 |
| `album` | `metadata.md` 提供的专辑名；同专辑的每首都一致 |
| `album_artist` | `metadata.md` 提供的专辑艺术家；同专辑的每首都一致 |
| `artist` | 使用该曲目的演唱者，或用户明确指定适用于该曲的默认演唱者。若都没有，报错并请用户提供；专辑艺术家只有经用户确认也是演唱者时才可复用 |
| `disc` | 多碟专辑有资料时填写，例如 `1/2` |
| `date`、`genre`、`composer`、`comment` | 可选；按 `metadata.md` 提供的发行日期、曲风、作曲者、备注写入，未知留空 |

封面支持 JPG 和 PNG。若成品专辑目录已有 `cover.jpg` 或 `cover.png`，保留已有封面；否则从工作目录复制 `cover.jpg`、`cover.png` 或用户指定的 JPG／PNG 封面。按实际格式命名为 `cover.jpg` 或 `cover.png`，无需转换格式。若同一位置有两个候选且未指定用哪张，先请用户选择；没有封面就跳过。`timestamps.png` 是切分资料，除非用户明确指定，否则不要拿它当封面。

## 打包成品和源文件

歌曲验证通过后，把整个成品子目录压缩成同名 ZIP，放在工作目录里，例如 `运河/运河.zip`。ZIP 解压后应先看到一层 `运河/`，里面是全部 M4A 和可选的 `cover.jpg` 或 `cover.png`。只打包成品，排除原 MP4、时间戳、`metadata.md`、临时文件和系统隐藏文件。若同名 ZIP 已存在，先报告冲突，不覆盖。

另在同一个工作目录创建 `<专辑名>_source.zip`，例如 `运河/运河_source.zip`，用于归档重剪所需的资料。压缩包内只放以下文件：

- 本次使用的原始整专 MP4，保留原文件名。
- `metadata.md`。
- 本次使用的原始时间戳文件（`timestamps.md`、`time_stamp.md` 或 `timestamps.png`）。如果用图片识别后另存了 Markdown 曲目表，两份一起归档。
- 本次使用的封面（若有），按实际格式归档为 `cover.jpg` 或 `cover.png`；如果封面只在成品子目录里，从那里取用。

源文件包不包含 M4A、成品 ZIP 或临时文件。若同名源文件包已存在，先报告冲突，不覆盖。

预期交付结构：

```text
运河/                       ← 工作目录
├── 运河整专.mp4
├── timestamps.md           ← 或 timestamps.png
├── metadata.md
├── 运河/                   ← 可整夹上传的成品
│   ├── 01-第一首歌名.m4a
│   ├── 02-第二首歌名.m4a
│   └── cover.png           ← 可选，也可以是 cover.jpg
├── 运河.zip                ← 内含同名成品文件夹
└── 运河_source.zip         ← 原 MP4、时间戳、metadata.md 和可选封面
```

## 验证和交付

1. 确认曲目表有 N 首就生成了 N 个 M4A，文件名和顺序一一对应。
2. 用 `ffprobe` 检查每个文件的音轨、时长及 `title`、`artist`、`album`、`album_artist`、`track` 标签。若时长明显偏离预期或标签不对，修正并重新验证；如果无法修正，指出受影响的曲目。
3. 用 `unzip -t` 检查两个 ZIP，再用 `unzip -l` 核对内容：成品包有同名目录、全部歌曲和可选封面；源文件包有本次使用的原 MP4、时间戳、`metadata.md` 和可选封面。
4. 汇报成品目录、两个 ZIP 的路径、曲目数、文件清单、未提供的可选标签，以及哪些曲目复制了原音轨、哪些经过了编码。提醒用户试听开头和结尾，确认切点符合预期。
