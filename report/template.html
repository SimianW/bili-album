系统结构

不受筛选影响
输入
web · cli
  • 网页上粘贴 B 站链接（BV 号、b23.tv 短链也行），一次处理一个，其余排队
  • 也可以用命令行：ingest 走同一条流程；plan / review / apply / import 可分步跑
①抓取与下载
bilibili · media
  • B 站接口：简介、分 P、章节、评论、封面
  • yt-dlp 下载 AAC 音轨，ffmpeg 流拷贝成 source.m4a，不重新编码
①四路证据
文字线索
hints
  • 章节、简介、评论里的时间戳；分 P 名
  • 标题里的专辑、歌手、年份；翻唱、cover、AI、「X版」等字样标出二创
曲库
catalog
  • 网易云 + iTunes：专辑、曲目、时长、年份、封面
  • 单曲归到歌手自己最早收这首歌的专辑，不用合辑；二创找原唱的最早发行
音频分析
analyze
  • 8 kHz 解码 → 静音、低谷、音色突变 → 候选切点（合集才跑）
  • 切在静音最深处的末尾，安静的前奏留给下一首
听歌识曲
recognize
  • Shazam 听 12 秒：歌名、歌手、录音起点；切点不晚于起点前 0.3 秒
  • 对齐干净时只抽查首、中、尾 3 首；顺序和曲库不符时按听到的顺序重排
①融合成方案
plan · align
  • 判类型：分 P / 合集 / 单曲（9 分钟以内）
  • 时间戳吸附到 3 秒内的候选点；没有就按曲库时长做动态规划对齐
  • 外语歌名用原文；中文全部转简体（日文不动）
  • 每首给置信度，疑点写进清单 → plan.json
plan.json
②Sol 复核
review
  • 模型读方案摘要，只能提修改：换专辑、改歌名歌手、重排、删或拆曲、移切点、标二创，最多重新分析一次
  • 每处修改都要曲库、识曲、测得的候选切点或 UP 主文字确认才生效，否则拒绝
  • 结论：通过 / 修改 / 交给人；复核失败时方案原样保留
没问题
③切分与写标签
apply · tag · media
  • 校验方案 → ffmpeg 流拷贝切分
  • 写标签、内嵌封面；核对时长（误差 ≤ 0.1 秒）
④导入 Jellyfin
library
  • 经隐藏临时文件夹拷进 <专辑歌手>/<专辑>/（单曲 <歌手>/<专辑>/）
  • 触发扫描，等专辑和全部曲目出现
  • Jellyfin 自己改成繁体的名字改回简体并锁定
  • 库里已有这张专辑时不覆盖，停下问：替换或保留原来的
音乐库
  • Jellyfin 里出现这张专辑
  • 网页给出「打开音乐库」链接
仍拿不准
停下等你确认
  • 网页列出 Sol 的说明和要看的曲目
  • 改歌名歌手后「确认并导入」，或「放弃」
  • 方案有硬伤（时间重叠等）时不让继续
确认后继续

① – ④ 是 pipeline 按顺序调度的四步：方案（plan，含抓取、四路证据和融合）→ 复核 → 切分 → 导入。它在拿不准或库里已有专辑时停下，每步都把进度写进 job.json，网页 web 和命令行 ingest 都调用它。

三条固定规则

二创视频（翻唱、改编、AI 翻唱等）填原唱，并且一律停下确认；外语歌名用原文，不用商店里的译名；中文一律写成简体，台港发行也一样（日文不转换）。

共用模块：net 带磁盘缓存、按站点限速、失败重试的 HTTP 客户端（B 站接口、曲库、封面，以及不缓存的模型代理和 Jellyfin 请求）· media 调用 ffprobe / ffmpeg：读音频信息、无损切分、裁封面 · textnorm 统一名称写法（繁转简、全角转半角、花体字母、标点）并做模糊匹配 · config 读机器配置（模型地址、Jellyfin、音乐库目录），密钥不进日志 · messages 把错误和问题翻成给人看的简体中文

每种模式能用哪些证据

模式文字线索曲库音频分析听歌识曲
带 UP 主时间戳✓✓✓✓1
盲测—2✓✓✓1
盲测（不识曲）—2✓✓—
  1. 1 有文字线索时只对置信度低于 0.8 的歌识曲；盲测里曲库对齐干净时抽查 3 首，有不一致或对不齐才每首都查；单曲总会识曲。
  2. 2 不读章节、简介、评论和分 P 名（--no-text-hints）；视频标题仍用来猜专辑、歌手和歌名，复核时模型也看不到 UP 主的文字。
  3. 页面顶上的「复核」是另一个独立开关：每种模式都先有工具自己的方案，再交给 Sol 复核，评测给两份方案分别打分。

评测怎么跑出这个页面

eval/cases.yaml15 个带标准答案的视频
eval/run_eval.py每个视频跑三种模式：先出方案，再 Sol 复核；带时间戳模式按复核后的方案切分并检查文件
eval/scoring.py给工具单独和复核后两份方案分别打分：类型、切点、歌名、歌手、专辑、标签、耗时
eval/results/results.json每次运行的两份结果和分数
report/build_report.py把结果嵌进页面模板，同时嵌入改进前的存档 eval/results/baseline/results.json（--baseline）
这个页面
模块一览
模块负责什么对接的外部工具或服务
web网页和 JSON 接口：粘贴链接、排队、停下时改歌名歌手再确认、替换或保留已有专辑（server · jobs · runner · urls · fake）浏览器（只收到 Jellyfin 的公开地址这一个配置值）；处理交给 pipeline
cli命令行：plan / apply / run / inspect / review / import / ingest / serve，打印摘要表无
pipeline调度四步（方案 → 复核 → 切分 → 导入），拿不准时停下；进度写进 job.json；confirm / discard 继续或放弃无（经其他模块）
plan调度抓取和四路证据、判类型、融合证据，写出 plan.json 和各阶段耗时；所有标签转简体无（经其他模块）
review给模型发方案摘要，只接受封闭清单里的修改，逐条用数据核实后才改；最多重新分析一次模型代理（OpenAI 兼容的 /chat/completions）、曲库查找（经 catalog）
library拷进音乐库目录、触发扫描并等专辑出现、把繁体名改回简体并锁定Jellyfin API、音乐库文件夹
bilibili解析链接，读页面信息、分 P、章节、评论、封面，下载音轨B 站接口、yt-dlp、ffmpeg
hints从文字里解析时间戳曲目表、分 P 名、标题里的专辑和歌手、二创字样、--tracklist 文件无
catalog搜专辑和单曲并按名字、总时长、曲目表排序；选单曲的原始发行和二创的原唱；补流派、封面、日期、歌词和作曲网易云、iTunes
analyze低采样率解码，算音量和频带特征，找静音、低谷、音色突变候选点ffmpeg
align把曲库时长按动态规划对到候选点上；把粗略时间吸附到附近候选点无
recognize截 12 秒片段识曲，结果缓存、限速，每次运行有请求上限Shazam（shazamio）、ffmpeg
apply校验 plan.json，切分、写标签、放封面，核对结果，可选打包ffmpeg / ffprobe（经 media）
tag读写 MP4 标签和封面无（mutagen 库）
media读音频信息、无损切分、准备本地音频、裁剪封面ffmpeg / ffprobe
net带缓存、限速和重试的 HTTP 客户端，只发通用 User-AgentB 站接口、网易云、iTunes、封面下载、模型代理、Jellyfin（Shazam 和 yt-dlp 不经过它）
textnorm名称归一（繁简、全半角、花体、标点）和相似度无
config读机器配置文件（模型、Jellyfin、音乐库目录），环境变量优先；密钥不进日志无
messages把错误和方案硬伤翻成给人看的简体中文，附稳定的错误代码无
__init__版本号和 User-Agent 字符串无
